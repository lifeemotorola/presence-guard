# OBS Beautifier

A plugin that changes how OBS Studio looks. It puts a skin on top of whatever
theme you are already using: accent colour, rounded corners, density, font size
and a handful of details, adjustable live from a dock.

| | |
|---|---|
| OBS version | built against **33.0.1** headers |
| Runtime deps | none beyond the Qt6 libraries OBS already ships |
| Kind | frontend dock, restyles the whole application |
| Config | `%APPDATA%\obs-studio\plugin_config\obs-beautifier\settings.json` |
| Tests | `tests/run-tests.sh` — the look is generated by pure C++ |

## What it actually does

OBS draws itself with Qt stylesheets: the active theme is a sheet that OBS hands
to `QApplication`. OBS Beautifier generates a **second** sheet and appends it, so
your theme stays underneath and our rules win where they overlap. Take our layer
away and OBS is byte-for-byte back to what it was before — which is exactly what
the Revert button and `obs_module_unload` do.

Because it appends instead of replacing, it works with **any** OBS theme, light
or dark: the colours are derived from OBS's own palette (window, text,
highlight), and every text colour is checked against its background before it
goes into the sheet. The tests enforce that — body text at 8:1, dim text at
4.5:1, text on the accent at 4.5:1 — so the skin cannot turn OBS into an
unreadable grey mush.

What is styled: window and dialogs, menus and menu bar, buttons and tool
buttons, inputs, combo boxes and their popups, checkboxes and radio buttons,
sliders, progress bars, tabs, scrollbars, group boxes, dock titles, list and
tree views (including the scene and sources lists), table headers, status bar,
tooltips and splitters.

What is not: **layout**. A stylesheet cannot move OBS's docks around, so the
plugin restyles and compacts, it does not rearrange.

## Get it

1. **Actions → OBS Beautifier → the newest green run → Artifacts →
   `obs-beautifier-windows-x64`.** The artifact is a zip inside a zip; extract
   twice.
2. Close OBS, then in the extracted folder:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Install.ps1
   ```

   It installs to `C:\ProgramData\obs-studio\plugins\obs-beautifier\`:

   ```
   C:\ProgramData\obs-studio\plugins\obs-beautifier\obs-beautifier.dll
   C:\ProgramData\obs-studio\plugins\obs-beautifier\data\locale\en-US.ini
   ```

   On OBS **32 or older** add `-LegacyLayout`; `Uninstall.ps1` removes either
   layout.
3. Restart OBS → **Docks → OBS Beautifier**.

## Use it

| Control | What it does |
|---|---|
| **Beautify OBS** | the whole skin on or off |
| **Preset** | Studio Amber, Graphite Compact, Nord, Lagoon, Magenta, High Contrast — a starting point, every field stays adjustable |
| **Accent** | *Use the theme's accent*, or pick any colour (it shows you the hex and picks readable text for it) |
| **Corner radius** | 0 px (sharp, OBS-like) to 20 px |
| **Density** | Compact, Normal, Comfortable — padding of buttons, inputs and menu rows |
| **Font size** | 90% to 130% of OBS's own font size |
| **Rounded buttons**, **Accent underline on tabs**, **Slim scrollbars**, **Compact dock titles** | the details, each switchable |
| **Revert to the OBS theme** | removes the layer and switches the plugin off, keeping your settings |

Everything applies as you change it (debounced by 140 ms so dragging a slider
restyles once, not fifty times). The skin is remembered and re-applied at
startup, and put back automatically when OBS switches theme.

If something looks wrong, **Revert** is always there — and so is deleting
`%APPDATA%\obs-studio\plugin_config\obs-beautifier\`.

## Build it

Self-contained: its own `buildspec.json`, `CMakePresets.json` and workflow.

**In the cloud (no compiler needed)** — push, then **Actions → OBS Beautifier**.
The workflow runs the look tests on Ubuntu, then builds on a Windows runner with
OBS 33.0.1 headers and Qt6 and uploads `obs-beautifier-windows-x64`.

**Locally** — from this folder, in a Visual Studio 2022 prompt:

```powershell
cmake --preset windows-x64
cmake --build --preset windows-x64 --config RelWithDebInfo
cmake --install build_x64 --config RelWithDebInfo --prefix build_x64\install
```

The look itself is pure C++17 — no OBS, no Qt — so its tests run anywhere:

```bash
./tests/run-tests.sh
```

91 checks: colour parsing and mixing, WCAG contrast maths, option clamping, the
resolved palette for dark *and* light themes, every option visibly changing the
sheet, and structural checks on the generated QSS (balanced rules, well-formed
colours, every major widget family styled, deterministic output).

## Layout

```
obs-beautifier/
├─ src/
│ ├─ beautifier-core.hpp/.cpp   colour maths + the generated stylesheet (no Qt)
│ ├─ beautifier.hpp/.cpp        applies and removes the layer (Qt + libobs)
│ ├─ beautifier-dock.hpp/.cpp   the dock
│ └─ plugin-main.cpp            module load/unload, dock, frontend events
├─ data/locale/en-US.ini
├─ tests/                       the look tests and their runner
└─ windows/                     Install.ps1, Uninstall.ps1
```
